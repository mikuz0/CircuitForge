Вот описание текущей модели компонента (Component) простыми словами, без кода, как она сейчас устроена в CircuitForge:
Суть
Компонент — это текстовое описание (в формате JSON) любого физического устройства, у которого есть выводы (порты). Это «чертёж» или «паспорт» детали, который хранится в отдельном файле в папке проекта (например, resistor-0603.cfcomp).
Модель состоит из двух частей: самого компонента и его портов.

1. Сам компонент (его общие свойства)
У каждого компонента есть:
    • schemaVersion — номер версии формата (сейчас 1). Нужен, чтобы в будущем, если мы изменим структуру файла, программа понимала, как читать старые файлы.
    • name (Наименование) — имя компонента, которое видит пользователь (например, "STM32F103C8T6" или "Резистор 0603"). Оно должно быть уникальным внутри проекта.
    • description (Описание) — короткая справка (например, "ARM Cortex-M3 MCU, 64KB Flash"). Может быть пустым.
    • model3dPath (Путь к 3D-модели) — необязательное поле. Ссылка на файл 3D-модели (STEP, WRL и т.д.). Если модели нет — поле пустое (null).
    • refPrefix (Префикс позиционного обозначения) — недавно добавленное поле. Это буквенный код, который будет использоваться в перечне элементов (ПЭ3). Например, для резисторов — "R", для конденсаторов — "C", для микросхем — "DD" или "U". Пользователь задаёт его сам.
    • В перспективе «Таблица основных свойств» - не показывается в главном окне, но хранится в том же файле. Сопротивление, ёмкость, мощность , рабочее напряжение, в зависимости от наименования. Поставить в соответствие префиксу. R — сопротивление, размер, мощность.., C — емкость, напряжение ….

2. Порты (выводы компонента)
Внутри компонента лежит список портов (ports). Количество портов не ограничено (от 0 до сотен).
Каждый порт описывает один физический вывод детали:
    • number — порядковый номер строки в таблице редактора (1, 2, 3...). Нужен для того, чтобы пользователь мог менять порядок отображения портов.
    • pinNumber — физический номер вывода. Это строка (текст), а не число, потому что номера бывают буквенными: "A1", "B12", "EP" (оголённая площадка), "GND".
    • name — функциональное имя вывода (например, "TX1", "GPIO22", "VCC").
    • description — краткое пояснение, зачем нужен этот вывод (например, "UART1 transmit"). Может быть пустым.

Как это выглядит в файле (пример)
Если открыть файл компонента в блокноте, это выглядит примерно так:
json
{
  "schemaVersion": 1,
  "name": "STM32F103C8T6",
  "description": "ARM Cortex-M3 MCU, 64KB Flash",
  "model3dPath": "models/stm32.step",
  "refPrefix": "DD",
  "ports": [
    {
      "number": 1,
      "pinNumber": "1",
      "name": "VBAT",
      "description": "Battery supply"
    },
    {
      "number": 2,
      "pinNumber": "2",
      "name": "PC13",
      "description": "GPIO / TAMPER-RTC"
    }
  ]
}
Краткий итог: Компонент знает, как он называется, как выглядит (3D), какую букву использовать для нумерации в BOM (refPrefix), и имеет подробную таблицу своих выводов (портов) с номерами и описаниями.
