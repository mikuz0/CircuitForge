Вот описание модуля «Менеджер проектов» (Project Manager) простыми словами, с учётом текущей реализации.

Назначение
Менеджер проектов — это главное окно (точка входа) приложения CircuitForge. Его задача — служить «рабочим столом» инженера: здесь он выбирает, где хранятся его работы, создаёт новые проекты и запускает остальные модули (ПЭ3, Связи, Компоненты) для конкретного проекта.

Основные понятия
    • Рабочая область (Workspace) — это папка на диске, внутри которой лежат папки с проектами. Путь к ней запоминается приложением, чтобы при следующем запуске не искать её заново.
    • Проект — это папка внутри рабочей области. У проекта есть имя и файл-описание (project.cfproj), а также подпапки для компонентов (components/), связей (nets/) и будущих экспортов (exports/).

Что умеет Менеджер проектов
1. Выбор рабочей области
Пользователь нажимает кнопку «Choose workspace…» и указывает папку через системный диалог. Программа запоминает этот путь в настройках (~/.config/circuitforge/settings.json) и при следующем запуске автоматически открывает ту же самую папку. Все проекты внутри неё сразу отображаются в списке.
2. Просмотр списка проектов
Программа сканирует выбранную папку, находит все подпапки, в которых есть файл project.cfproj, и выводит их в виде списка. Список отсортирован по алфавиту. Если в папке нет проектов (или она пуста) — список будет пустым.
3. Создание нового проекта
В поле «New project name» пользователь вводит имя (например, my_board) и нажимает «Create». Программа:
    1. Проверяет, что имя не содержит запрещённых символов (типа / или \).
    2. Создаёт папку с этим именем внутри рабочей области.
    3. Создаёт внутри неё файл project.cfproj (с именем проекта и датой создания).
    4. Создаёт пустые подпапки components/, nets/, exports/.
    5. Обновляет список и автоматически выделяет только что созданный проект.
4. Запуск модулей
Когда проект выделен в списке, внизу становятся активными три кнопки:
    • «ПЭ3» (Перечень элементов)
    • «Связи» (Netlist)
    • «Компоненты» (Редактор деталей)
Нажатие на любую из них открывает соответствующее окно (в отдельном окне) и передаёт ему путь к папке выбранного проекта. Модуль сам загрузит нужные данные из этой папки. Если проект не выбран, кнопки неактивны (или выдают ошибку «Select a project first»).

Как это устроено внутри (архитектура)
    • Файл настроек: Приложение хранит выбранный Workspace в файле settings.json. Если файла нет, менеджер запускается «с чистого листа» и просит выбрать папку.
    • Фоновые операции: Все чтения и записи на диск (сканирование папок, создание проекта) выполняются в фоне (через Task), чтобы окно не «зависало».
    • Обмен данными: Менеджер не знает, что именно делают модули. Он просто создаёт окно модуля и вызывает у него метод openProject(путь). Модули сами решают, что им загружать.
    • Список проектов хранит не только имя, но и полный путь к папке (тип ProjectInfo), чтобы при запуске модуля передать точный адрес.

Ограничения и особенности
    • Нет вложенных проектов: Программа ищет project.cfproj только на один уровень вглубь от рабочей области. Если проект лежит в подпапке подпапки, он не найдётся.
    • Нет переименования/удаления: На текущем этапе проект можно только создать и открыть. Удаление или переименование проекта делается вручную средствами файловой системы (через проводник).
    • Безопасность: Ошибки при создании (например, папка уже существует) перехватываются и показываются пользователю в виде понятного диалогового окна с текстом ошибки.
    • Состояние: Если пользователь работал в модуле и что-то изменил, менеджер об этом не знает — он не управляет процессами сохранения в других модулях.
