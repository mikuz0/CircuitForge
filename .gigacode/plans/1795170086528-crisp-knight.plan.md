## Изменения формата schematic.json

**Было:**
```json
{
  "schemaVersion": 1,
  "nodes": [
    {"bomnetId": "uuid", "x": 500.0, "y": 300.0}
  ]
}
```

**Стало:**
```json
{
  "schemaVersion": 2,
  "nodes": [
    {"bomnetId": "uuid", "x": 500.0, "y": 300.0, "rotation": 0.0}
  ],
  "bendPoints": {
    "GND": [
      [{"x": 500.0, "y": 300.0}, {"x": 600.0, "y": 300.0}, {"x": 600.0, "y": 400.0}, {"x": 700.0, "y": 400.0}]
    ]
  }
}
```

**Обратная совместимость:**
- Если `bendPoints` отсутствует → используем CubicCurve (fallback)
- Если `rotation` отсутствует → дефолт 0.0

## Этап 2: ELK-адаптер

### Создать: `src/main/kotlin/ru/circuitforge/ui/schematic/layout/ElkGraphBuilder.kt`

**Задача:** Построить ELK-граф из BOM + Nets

**Алгоритм:**
1. Создать `org.eclipse.elk.core.data.ModelBuilder`
2. Создать корневой узел графа
3. Для каждого `BomRow`:
   - Создать узел ELK с размером (ширина, высота) из SVG-символа
   - Создать порты узла по `Component.ports`:
     - Сторона порта вычисляется по индексу:
       - Резистор/конденсатор: порт 0 → LEFT, порт 1 → RIGHT
       - IC: первые `mid = (ports.size + 1) / 2` → LEFT, остальные → RIGHT
     - `portConstraints = FIXED_SIDE`
4. Для каждой `Net`:
   - Если connections.size >= 2:
     - Создать рёбра цепочкой: conn[0] → conn[1] → conn[2] → ...
     - Рёбра связывают порты узлов по refDes
5. Установить опции:
   - `Direction.RIGHT`
   - `EdgeRouting.ORTHOGONAL`
   - `Spacing.NodeNode = 100`
   - `Spacing.EdgeNode = 50`
   - `Layered.spacing.nodeNodeBetweenDifferentLayers = 80`

### Создать: `src/main/kotlin/ru/circuitforge/ui/schematic/layout/ElkLayoutEngine.kt`

**Задача:** Запустить ELK и распарсить результат

**Вход:**
- `List<BomRow>` — строки BOM
- `List<Net>` — цепи
- `Map<String, Component>` — компоненты
- `Map<String, SchematicNode>` — существующие координаты (если есть)
- `boolean useExistingLayout` — использовать существующую раскладку или строить новую

**Выход:** `Pair<SchematicDocument, Map<String, List<List<Point>>>)` — узлы + bend points

**Алгоритм:**
1. Если `useExistingLayout` и есть координаты → вернуть их с пустыми bend points
2. Построить ELK-граф через `ElkGraphBuilder.build()`
3. Запустить `RecursiveGraphLayoutEngine().layout(graph, properties)`
4. Распарсить `LayoutMapping`:
   - Для каждого узла: `node.x, node.y` → округлить до 12.5 → `SchematicNode`
   - Для каждого ребра: `edge.sections[].bendPoints` → собрать точки
5. Вернуть `SchematicDocument` + `bendPoints` по имени цепи

            loadSvgFromResources("$key.svg") ?: loadSvgFromResources("default.svg")
        }
    }
    
    fun getSymbolSize(compName: String): Pair<Double, Double> {

**Реализация загрузки SVG:**

private fun drawPortConnections(activePorts: Set<String>) {
    linePane.children.clear()
    
    activePorts.forEach { activeKey ->
        val (activeRefDes, activePin) = activeKey.split(":", limit = 2)
        
        nets.forEach { net ->
            val hasActivePort = net.connections.any { conn ->
                conn.refDes == activeRefDes && conn.pinNumber == activePin
            }
            if (!hasActivePort) return@forEach
            
            // Проверить, есть ли bend points для этой цепи
            val netBendPoints = bendPointsMap[net.name]
            if (netBendPoints != null && netBendPoints.isNotEmpty()) {
                // Рисуем ортогональные провода по точкам изгиба
                netBendPoints.forEach { points ->
                    val polyline = Polyline(*points.toTypedArray())
                    polyline.stroke = netColor(net.name)
                    polyline.lineWidth = 2.0
                    polyline.opacity = 0.7
                    linePane.children.add(polyline)
                }
            } else {
                // Fallback: CubicCurve для ручной раскладки
                // ... существующая логика с CubicCurve ...
            }
        }
    }
    
    drawNetLabelsForActivePorts(activePorts)
}

## Риски и неизвестные моменты

1. **ELK 0.9.x и Java 21** — проверить совместимость, возможно нужен моду-патч
2. **SVGPath в JavaFX 21** — проверить, доступен ли `javafx.scene.shape.SVGPath`
3. **Производительность** — ELK может замедлять загрузку больших схем (>50 компонентов)
4. **Совместимость SVG** — не все SVG-парсеры поддерживают вложенные группы
5. **Bend points** — изменение формата schematic.json требует миграции старых файлов

## Альтернативы

Если ELK 0.9.x не совместим с Java 21:
- Использовать ELK 0.10.x (если есть)
- Рассмотреть другие layout-движки: yFiles, JGraphX
- Остаться на Grid/Force-directed layout, но улучшить алгоритм

Если SVGPath недоступен:
- Парсить SVG вручную и создавать JavaFX Path/Line/Rect
- Использовать внешнюю библиотеку для парсинга SVG (e.g., Batik)
