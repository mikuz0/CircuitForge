# План: Полное удаление ELK из проекта

## Проблема

Ошибка `org/eclipse/xtend/xbase/lib/CollectionLiterals` — транзитивная зависимость ELK (Eclipse Xtend). Несмотря на удаление кода ELK (ElkGraphBuilder.kt, ElkLayoutEngine.kt), зависимости остались в `build.gradle.kts` и в Gradle cache.

## Корневая причина

`build.gradle.kts` содержит ELK-зависимости:
```kotlin
implementation("org.eclipse.elk:org.eclipse.elk.core:0.12.1")
implementation("org.eclipse.elk:org.eclipse.elk.alg.layered:0.12.1")
```

Эти зависимости тянут за собой `org.eclipse.xtend:xtend.lib` → `CollectionLiterals.class`.

## Шаги исправления

### 1. Удалить ELK-зависимости из `build.gradle.kts`

**Файл:** `build.gradle.kts` (строки ~24-26)

Удалить блок:
```kotlin
// ELK Java — автоматическая раскладка схем
implementation("org.eclipse.elk:org.eclipse.elk.core:0.12.1")
implementation("org.eclipse.elk:org.eclipse.elk.alg.layered:0.12.1")
```

### 2. Очистить Gradle cache от ELK и Xtend

```bash
rm -rf ~/.gradle/caches/modules-2/files-2.1/org.eclipse.elk
rm -rf ~/.gradle/caches/modules-2/files-2.1/org.eclipse.xtend
rm -rf ~/.gradle/caches/modules-2/files-2.1/org.eclipse.xtext
```

### 3. Полная очистка и пересборка

```bash
./gradlew clean
./gradlew build --no-daemon
```

### 4. Проверка отсутствия ELK в classpath

```bash
# Проверить что ELK не в runtime classpath
./gradlew dependencies --configuration runtimeClasspath | grep -i elk
# Должно вернуть: (no output)

# Проверить что Xtend не в runtime classpath
./gradlew dependencies --configuration runtimeClasspath | grep -i xtend
# Должно вернуть: (no output)
```

### 5. Проверка сборки приложения

```bash
# Запустить приложение
./gradlew run
```

### 6. Проверка сборки deb-пакета (опционально)

```bash
./scripts/build-deb.sh
```
