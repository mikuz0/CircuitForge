# План: Поддержка нескольких *.json файлов в project/symbols/

## Проблема

Сейчас в проекте используется один `symbols.json` в `project/symbols/`. При создании компонентов из промта — весь комплект пишется в один файл. Неудобно для diff, версионирования и поддержки нескольких источников символов.

## Решение

Вместо одного `project/symbols/symbols.json` — несколько `project/symbols/*.json`. При загрузке SymbolLibrary:
1. Загружает базовый `resources/symbols/symbols.json`
2. Находит все `*.json` в `project/symbols/`
3. Мерджит их (последний файл имеет приоритет при конфликтах)

## Изменения

### Файл: `src/main/kotlin/ru/circuitforge/ui/schematic/symbols/SymbolLibrary.kt`

**Метод `fromProjectDir`:**

Текущая реализация загружает один `symbols.json`:
```kotlin
val configFile = symbolsDir.resolve("symbols.json")
if (Files.exists(configFile)) {
    val content = Files.readString(configFile)
    val projectConfig = json.decodeFromString(SymbolConfig.serializer(), content)
    config = mergeConfigs(baseConfig, projectConfig)
}
```

Новая реализация загружает все `*.json`:
```kotlin
if (Files.exists(symbolsDir) && Files.isDirectory(symbolsDir)) {
    Files.list(symbolsDir)
        .filter { it.toString().endsWith(".json") }
        .sorted()
        .forEach { configFile ->
            val content = Files.readString(configFile)
            val projectConfig = json.decodeFromString(SymbolConfig.serializer(), content)
            config = mergeConfigs(config, projectConfig)
            logger.info("Loaded symbol config from: $configFile")
        }
}
```

**Ключевые моменты:**
- `sorted()` — гарантирует детерминированный порядок загрузки (lexicographic)
- `mergeConfigs` — уже существующий метод, мерджит `symbols` и `mappings`
- Последний файл в sorted-порядке переопределяет предыдущие (putAll)
- Логирование: `info` при успешной загрузке, `warn` при ошибке

### Пример структуры проекта

```
project/
├── symbols/
│   ├── base.json              # общие символы (R, C, L)
│   ├── mcu.json               # микроконтроллеры
│   └── phy6222-symbols.json   # специфичные для проекта
```

### Обратная совместимость

- Старый `symbols.json` продолжит работать (будет загружен как один из файлов)
- Если `project/symbols/` не существует — используется только resources
- Если `project/symbols/` пуст — используется только resources

## Верификация

1. Создать два файла в `project/symbols/`: `a.json` и `b.json`
2. `a.json` определяет символ `Resistor`
3. `b.json` переопределяет `Resistor` (другие размеры)
4. Загрузить проект — должен использоваться `Resistor` из `b.json`
5. Проверить лог: `Loaded symbol config from: .../a.json` и `.../b.json`
6. Проверить что базовый из resources загружается первым
