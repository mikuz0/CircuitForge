Вот описание модуля «ПЭ3» (Перечень элементов / BOM) простыми словами, как он устроен в CircuitForge.

Назначение
Модуль ПЭ3 — это электронная спецификация (BOM), которая показывает, какие именно экземпляры компонентов используются в конкретном проекте. Если «Редактор компонентов» — это библиотека «паспортов» деталей (резистор, микросхема), то «ПЭ3» — это список «кто именно и сколько раз установлен на плате».

Как это выглядит для пользователя
Это окно с таблицей, где каждая строка — один установленный компонент:
#	RefDes	Component	Comment
1	R1	Resistor 0603	10k 1%
2	R2	Resistor 0603	4.7k
3	DD1	STM32F103C8T6	Main MCU
4	C1	Capacitor 0603	100nF
    • # — просто порядковый номер строки (пока 1, 2, 3...). Пользователь не редактирует.
    • RefDes (Позиционное обозначение) — уникальное имя экземпляра в проекте: R1, R2, DD1, C10. Это поле редактируется.
    • Component (Наименование) — ссылка на описание из библиотеки компонентов (подтягивается автоматически, вручную не редактируется).
    • Comment (Комментарий) — свободный текст: номинал, допуск, любые пометки. Редактируется.
В одном ПЭ3 может быть сколько угодно одинаковых компонентов — например, 50 резисторов будут 50 отдельными строками с разными RefDes.

Откуда берутся данные
    • Список компонентов берётся из папки <project>/components/ (тех самых .cfcomp файлов, которые создаются в Редакторе компонентов).
    • Сам список ПЭ3 хранится в отдельном файле <project>/bom.json (не смешивается с project.cfproj).
Файл bom.json выглядит так:
json
{
  "schemaVersion": 1,
  "items": [
    { "number": 1, "refDes": "R1", "componentSlug": "resistor-0603", "comment": "10k 1%" },
    { "number": 2, "refDes": "R2", "componentSlug": "resistor-0603", "comment": "4.7k" }
  ]
}
Здесь componentSlug — это ссылка на файл components/resistor-0603.cfcomp. Само имя («Resistor 0603») в bom.json не дублируется — оно подтягивается из библиотеки при открытии. Если компонент переименуют в редакторе, ПЭ3 покажет новое имя без правок.

Что умеет ПЭ3
1. Добавление (Add Item…)
Открывается окно со списком всех компонентов проекта. Пользователь выбирает нужный (например, Resistor 0603). Программа:
    1. Смотрит, какой префикс (refPrefix) задан у этого компонента (например, "R").
    2. Сканирует таблицу и ищет все существующие RefDes, начинающиеся с R, чтобы найти максимальный номер (R1 → R2 → ...).
    3. Создаёт новую строку с RefDes = "R3" и пустым комментарием.
2. Дублирование (Duplicate)
Копирует выбранную строку и присваивает ей следующий свободный RefDes. Удобно, когда на плате 10 одинаковых резисторов — не нужно каждый раз открывать диалог выбора.
3. Удаление (Delete)
Удаляет выбранную строку (с подтверждением, если есть что терять).
4. Редактирование на месте
Поля RefDes и Comment редактируются прямо в ячейках таблицы (двойной клик). Поле Component и # — только для чтения.
5. Сохранение (Save)
Перед записью:
    • Проверяет, что все RefDes заполнены и уникальны (если кто-то оставил пустое или случайно указал R1 дважды — покажет ошибку).
    • Перенумеровывает поле # (1, 2, 3...), чтобы порядок в файле совпадал с порядком строк в таблице.
    • Записывает bom.json.
6. Откат (Revert)
Отменяет все несохранённые правки и перечитывает файл с диска.
7. Защита от потери данных
Если при закрытии окна или переключении остаются несохранённые изменения, появляется диалог Save / Discard / Cancel.

Горячие клавиши (по аналогии с редактором компонентов)
    • Ctrl+S — сохранить
    • Ctrl+D — дублировать строку
    • Delete — удалить строку

Как модуль взаимодействует с другими частями приложения
    • С Менеджером проектов: открывается кнопкой «ПЭ3» из главного окна, получает путь к проекту.
    • С Редактором компонентов: читает файлы .cfcomp (только на чтение). Если компонент был удалён или переименован, ПЭ3 при следующей загрузке покажет актуальное состояние или <not found: slug>, если файла больше нет.
    • Со Связями (Net): пока не связан. В будущем Net будет ссылаться на RefDes из ПЭ3 (например, «R1.1 соединён с DD1.15»).

Что пока НЕ умеет (осознанные ограничения текущего этапа)
    • Ручная перестановка строк (drag & drop) — в планах. Сейчас порядок определяется порядком добавления.
    • Автоматическая перенумерация при удалении (если удалить R2 из R1, R2, R3 — останутся R1 и R3, «дырки» допустимы).
    • Группировка (свернуть все резисторы в одну строку с количеством) — в планах. Сейчас каждая деталь — отдельная строка.
    • Импорт из CSV/Excel — пока только ручное добавление и дублирование. (В будущем добавим массовый импорт.)
    • Проверка использования в схемах — если компонент используется в Связях, ПЭ3 об этом не предупреждает при удалении (потому что Связей пока нет).
